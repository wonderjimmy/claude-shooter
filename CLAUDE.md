# Claude Shooter

Browser-based horizontal scrolling shoot-'em-up. Player flies left-to-right, dodges bullets, fights waves and bosses. Visual ambition: heavy use of particles, glow, screen shake, shader-based distortion. Assets (sprites, SFX, music) are generated by Jimmy and dropped into `assets/`.

## Stack

- **PixiJS v8** — WebGL 2D renderer. All drawing goes through Pixi.
- **pixi-filters** — extra filters (BloomFilter, CRTFilter, etc.) on top of Pixi v8 core.
- **lil-gui** — runtime tuning panel for visual params; dev-time UI only.
- **Vite** — dev server + bundler. `pnpm dev` / `npm run dev` opens at :5173.
- **TypeScript strict** — `noUnusedLocals`, `noUnusedParameters`, `noImplicitOverride` are on.

No game framework on top of Pixi (no Phaser). The game loop, entity registry, and systems are hand-written so we keep full control over the visual pipeline.

## Architecture

  game/

### Layering

`Game.layers` defines z-order from back to front: `bg` → `entities` → `fx` → `ui`. Don't add children directly to `app.stage` — go through a layer.

### Game loop

`app.ticker` drives everything. Each tick: drain `pending` spawns → `update(dt)` every live entity → compact dead entities → `input.endFrame()`. `dt` is Pixi's `deltaTime` (≈1 at 60fps); multiply movement by `dt` so behavior is framerate-independent.

### Entity contract

- Construct with `(game, …)`. Entity adds its own `view` to `Game.layers.entities` via `game.spawn(this)`.
- Implement `update(dt)`. Use `this.game` to spawn children (bullets, particles).
- Set `this.dead = true` or call `destroy()` to remove. The registry sweeps dead entities each tick.
- `radius` is the collision circle. Keep it honest — visual size and collision radius can differ.

### Spawning

Always `game.spawn(entity)`. Never push to the entity array directly — pending list lets entities spawn during iteration without mutating mid-loop.

## Boss design

`Boss` is a single Entity (not composed sub-parts yet — that's a polish step). The `BOSS_PHASES` table in `Boss.ts` drives the state machine:

- **Stage 1** (`bossStage1`, 60 HP, scale 0.7) — slow `spread` fan of 5 bullets every 80 frames. Big telegraphic motion, easy phase.
- **Stage 2** (`bossStage2`, 50 HP, scale 0.85) — `aimed` 4-bullet fan tracking the player every 55 frames. Medium pressure.
- **Stage 3** (`bossStage3`, 50 HP, scale 1.0) — `hell` mode: 10-bullet rotating ring + aimed shot every 32 frames. Bullet hell finale.

When stage HP reaches 0, `advanceStage()` swaps the texture, resets HP for the next phase, and calls `Game.bossPhaseTransition()` which emits a yellow particle burst, large explosion sprite, screen shake, and chromatic punch — the visual "tell" that the phase changed.

Boss spawns when `score >= BOSS_SCORE_THRESHOLD` (2500). On spawn: `Spawner.paused = true`, alive enemies are killed, `playBgm('boss')` crossfades, boss HP bar appears at the bottom of the screen. On boss death: `triggerWin()` shows VICTORY overlay, fades BGM, awaits R to restart.

A 90-frame slide-in entry (cubic ease) gives a moment of i-frames so the boss can't be cheesed before its first attack.

## Asset pipeline

The `Carrion Ix` asset pack (bio-mechanical R-Type style, designed in Claude Design) lives in:

- `assets/images/sprites/` — 30 SVGs: player ship, 5 enemies, 3 boss stages, 8 projectiles, 8 power-ups, 2 FX, 3 parallax tiles.
- `assets/audio/` — `.mp3` / `.ogg` / `.wav`. BGM (`bgm-normal`, `bgm-boss`) + SFX (`sfx-shoot`, `sfx-hit`, `sfx-explode`, `sfx-damage`, …).

Audio loading: `src/game/audio/manifest.ts` is the single edit point. Drop file into `assets/audio/`, uncomment the matching `import` + `audio.register*` line, refresh. Vite resolves the URL; `AudioManager` handles pool / crossfade / volume.

`src/game/assets/sprites.ts` is the single source of truth:
- `SPRITE_URLS` — typed map alias → URL (Vite resolves SVG imports).
- `loadSprites()` — async; `Assets.add(records)` then `Assets.load`. **Must `await` before `Game.create`** (see `main.ts`).
- `tex(key)` — strongly-typed Texture lookup. Throws if called before `loadSprites()`.

Adding new assets:
1. Drop SVG into `assets/images/sprites/`
2. Add `import url from '...'` + entry in `SPRITE_URLS` in `sprites.ts`
3. Use `tex('alias')` in entity code

SVGs are rasterised by Pixi at default resolution. For crisper retina, pass `data: { resolution: 2 }` to `Assets.load`.

The named CSS classes baked into each SVG (`.cockpit`, `.engine-glow`, `.scythe-1`, etc.) are **not used** in the Pixi pipeline — animation comes from particles, filters, and Pixi tweens, not embedded CSS. Reference `Game Assets.html` from the design bundle if you ever need to inline-render an SVG and replay the design's hover animations.

## Visual ambition checklist

When a feature lands, ask: does it look generic? If yes, layer at least one of:
- Particles on impact / death / muzzle
- Screen shake on heavy hits (trauma model, not flat shake)
- Glow / bloom on bullets and explosions
- Background parallax (≥3 layers, different scroll rates)
- Color grading via a global filter

## Conventions

- **TypeScript strict, no exceptions.** Don't disable strict flags to make code compile — fix the type.
- **Keep `config.ts` as the single source of tunables.** Don't sprinkle magic numbers in entity code.
- **No comments unless the WHY is non-obvious.** The code's job is to be readable; comments are for hidden constraints.
- **No premature abstractions.** Three similar entities is fine — extract a base only when the duplication actually hurts.
- **Per-frame allocations matter.** Avoid `new` inside `update()` for hot paths (bullets, particles). Pool when we measure pressure.
- **All world-space drawing goes through a layer.** No `app.stage.addChild` in entity code.

## Difficulty

`Game.difficulty: 'normal' | 'hard'`. Persisted to `localStorage('claude-shooter:difficulty')`. Multipliers in `DIFFICULTY_MULS`:

| | enemyHp | enemySpeed | enemyFire | bossHp | bossFire | dropRate | threshold |
|---|---|---|---|---|---|---|---|
| normal | 1.0 | 1.00 | 1.00 | 1.0 | 1.00 | 0.20 | 7000 |
| hard   | 1.5 | 1.18 | 0.70 | 1.4 | 0.70 | 0.13 | 9000 |

`enemyFire` / `bossFire` < 1 = fire faster (interval scaled). Enemy & Boss read `game.muls` in their constructor to scale spec; Boss `advanceStage()` re-scales per phase. HUD shows a small badge bottom-left (`NORMAL [H]` / `HARD [H]`).

## Power-ups

Killed enemies have a 12% chance to drop a pickup. Pickups drift left, bob, rotate, and alpha-pulse — collected on player overlap (no i-frame check). 8 kinds:

| kind | sprite | effect |
|---|---|---|
| `shield` | puShield | 6s invincibility (cyan tint, alpha pulse) |
| `spread` | puSpread | 9s 3-bullet spread fire |
| `speed` | puSpeed | 9s player speed × 1.5 |
| `multi` | puMulti | 9s fire rate × 2 |
| `laser` | puLaser | 9s big piercing laser bullet (proj-charge sprite) |
| `life` | puLife | +1 HP (capped at maxHp) |
| `bomb` | puBomb | clear all enemy bullets + 2 damage to all enemies & boss |
| `coin` | puCoin | +500 score |

Effect timing is driven by `Game.gameTime` (frame counter) + `*Until` fields. `Player.update()` reads those each frame to decide spread / speed / fireRate / laser. `Player.invincible` returns true if i-frames OR shield active.

## Game state

`Game` owns the run state: `score`, `playerHp` / `playerMaxHp`, `gameOver`, `won`, `bossSpawned`, `boss`. Mutations go through:
- `onHit(x, y, killed, kind)` — player bullet hit a regular enemy
- `onBossHit(x, y, killed)` — player bullet hit boss
- `onPlayerHit(source)` — player took damage (rammed by enemy / boss / hit by enemy bullet)
- `bossPhaseTransition(x, y)` — fired by `Boss.advanceStage()`

When `playerHp <= 0` → `triggerGameOver()`. When boss dies → `triggerWin()`. Both stop BGM, show overlay, await **R**. `restart()` destroys non-player entities (including stale boss), resets player + spawner + HUD + boss state + BGM.

Score per kill: wasp 100 / cyborg 150 / brain 200 / mantis 250 / crystal 300 / boss kill 5000. Boss spawns at score 2500.

## Filter stack

The visual pipeline stacks filters in two places. Order matters.

- **`Game.layers.entities.filters = [BloomFilter]`** — bloom only on entity layer so background stars don't smear into a haze.
- **`Game.app.stage.filters = [ChromaticAberrationFilter, ColorMatrixFilter]`** — applied to whole frame after world transform & shake. Chromatic before color so the RGB-split happens on already-graded pixels.

`Game.filters` exposes `{ bloom, chromatic, color }`. `Game.chromaticBase` is the resting chromatic strength; `Game.onHit()` adds a transient `chromaticPunch` that decays each tick — that's the punch on enemy deaths.

Color grading is driven by three numbers on `Game`: `colorSaturation`, `colorBrightness`, `colorContrast`. `Game.applyColorGrading()` rebuilds the matrix from those. The defaults push toward arcade-bright (sat +0.4, brightness 1.15, contrast 0.15). Call `applyColorGrading()` after mutating any of the three.

CRTFilter was tried but removed — the scan-line + curvature look fought with the SVG art. If you ever want it back, it's a one-line `import { CRTFilter } from 'pixi-filters'` away.

### Custom shader

`ChromaticAberrationFilter` is a hand-written Pixi v8 `Filter` with raw GLSL fragment shader and a `chromaticUniforms` UniformGroup (`uStrength`, `uRadial`). It's the reference for adding more custom shaders (energy wave, heat haze, glitch). Pattern to copy:

1. Write `vertex` + `fragment` GLSL (note: ES 3.0 — use `in`/`out` and `texture()`, not `gl_FragColor`).
2. `GlProgram.from({ vertex, fragment, name })` and pass to `super({ glProgram, resources: { yourUniforms: {...} } })`.
3. Cache `(this.resources.yourUniforms as { uniforms: T }).uniforms` so getter/setter is one hop.

WGSL (WebGPU) version isn't wired — Pixi will fall back to GL on browsers without WebGPU support, which is fine for now.

## Tuning panel

`src/game/ui/Tuning.ts` mounts a `lil-gui` panel (top right). Bound to live filter / scene properties: bloom strength, color grade (saturation / brightness / contrast), chromatic base/radial, audio volumes + mute button, per-layer background alpha / speed / tileScale. Folder is closed by default — open while tweaking. **The panel is dev-only**; before any "real release" it should be gated behind a `?tune` query param or env var.

All tuning values persist to `localStorage` (`claude-shooter:tuning`) on every change. Audio volumes persist separately (`claude-shooter:audio`) and load in `AudioManager` constructor. **Reset to defaults** wipes both keys and restores the factory snapshot captured at first load.

## Project status (May 2026)

**Feature-complete personal project**. Tuning panel gated behind `?tune` query param. See [README.md](README.md#deployment-notes) for the full deployment journey:

- Web ship via Cloudflare Workers works for users without SES-injecting extensions (~70-85% depending on audience).
- Browser extensions like MetaMask / Coinbase Wallet / Claude in Chrome inject SES lockdown that breaks PixiJS shader compilation. iframe sandbox doesn't escape (chext uses `all_frames: true`).
- Tauri desktop boots but lags on Mac (WKWebView WebGL2 is weaker than Chromium).
- Electron desktop hangs at `Application.init()` — root cause unknown, possibly Pixi v8 + Electron 42 + macOS GPU race.
- Boot-time detection in [main.ts](src/main.ts) surfaces clear `EXTENSION CONFLICT` overlay instead of black screen, with `chrome://extensions` instructions.

`src-tauri/` and `electron/` scaffolds are kept in repo as archive but neither produces a usable distributable today.
